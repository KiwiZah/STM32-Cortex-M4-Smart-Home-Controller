# Build and reproduction guide

## Tools

- ST **STM32CubeIDE**, configured with a current ARM embedded GCC toolchain, or compatible ARM compiler.
- ST **STM32CubeL4** firmware package for the **32L476GDISCOVERY** development board.
- Correctly powered STM32L476G-DISCO board, keypad and separately powered servo/lamp driver (only if optional hardware testing is desired).

## A. Standalone EXTI / LED exercise (original source)

1. Open STM32CubeIDE.
2. Choose **File > Import > General > Existing Projects into Workspace**.
3. Under **Select root directory**, choose `firmware/blink-test/`.
4. Import the project, then **Project > Build Project**.
5. This code uses direct registers for PA0 button EXTI0, PB2 red LED and PE8 green LED.
6. The startup file and linker scripts are included; the project does not include the historical `Debug/` directory because build products are regenerated by the IDE.

## B. Integrated keypad/LCD/servo/lamp demonstration (reconstructed source)

1. Download/install the official STM32CubeL4 firmware package and open the package's **`Projects/32L476GDISCOVERY/Examples/BSP`** STM32CubeIDE example. The recovered historical `.project` references external STM32CubeL4 source and header files, which were not included in the user's archive.
2. **Back up the official example** before altering it.
3. Copy `firmware/reconstructed/main.c` into the BSP example's `Src/main.c` (or update the linked `User/main.c` resource path inside CubeIDE).
4. Copy `firmware/reconstructed/password_check.s` to the BSP example project. Ensure CubeIDE compiles and links the `.s` file with the C application.
5. Ensure BSP headers `stm32l476g_discovery.h` and `stm32l476g_discovery_glass_lcd.h`, plus STM32 HAL and CMSIS headers, are in the project include paths.
6. Verify the target MCU is **STM32L476VGTx**, the startup code and linker script match the board, then build in CubeIDE.
7. **Optional:** attach correct external hardware using the recovered pin map before flashing. The current reconstruction may need small adjustments for your particular installed STM32CubeL4 version, LCD API or hardware wiring; it was not physically tested as part of this repository cleanup.

**Important:** Do not replace the fully recovered historical binary with the rebuilt application and claim they are identical; the recovered source is a reimplementation based on disassembly.

## Source-only validation, with no board

The following commands are available when `clang` and `python3` are installed:

```sh
python3 -m unittest discover -s tests -v
clang -target armv7em-none-eabi -mthumb -c firmware/reconstructed/password_check.s -o /tmp/password_check.o
clang -target armv7em-none-eabi -mthumb -fsyntax-only firmware/blink-test/main.c
```

The integrated `main.c` additionally depends on the ST HAL/BSP headers; a syntax-only check with stub headers can verify C syntax, but does not establish a real board build.
